# 先把路线长度算对

## 一条路线包含什么

城市坐标是 `2×N` 矩阵，每列一个城市；路线是 `1:N` 的一个排列，例如 `[2 1 3]`。排列不重复保存起点，但计算时必须包含最后一个城市回到第一个城市的边。

给定：

```matlab
D = [0 3 5; 3 0 4; 5 4 0];
route = [2 1 3];
```

正确路线为 `2 → 1 → 3 → 2`，长度是 `3 + 5 + 4 = 12`。旧代码把末边写成 `D(length(route),1)`，这里变成 `3 + 5 + 5 = 13`。如果路线碰巧从 1 开始且最后一个城市正好为 N，错误可能被掩盖，所以回归用例特意打乱了端点。

公共入口 `tsp.routeLength` 校验矩阵和排列，再把相邻城市向量与循环平移后的向量配对。内部求解器只对自身已验证且保持排列不变的路线调用 `tsp.costUnchecked`，避免每次评价都扫描整个距离矩阵。

对称 TSP 的同一条环旋转起点或反向访问，长度应相同。测试也验证了这两个不变量。单城市路线长度为 0；双城市会把往返两条边都计入。

## ATT 不是普通欧式距离

ATT48 使用 TSPLIB 的 ATT 规则。对于两个不同城市，令：

```text
r = sqrt((dx^2 + dy^2) / 10)
t = round(r)
d = t + 1  （当 t < r）
d = t      （否则）
```

自环距离为 0。例如坐标差为 (3,4)，r 约为 1.581，最终距离为 2；差为 (1,3)，r 为 1，最终距离为 1。仅使用 `sqrt(.../10)` 会定义另一个优化问题。

`tsp.distanceMatrix` 提供三种明确模式：

| 模式 | 定义 | 用途 |
| --- | --- | --- |
| ATT（默认） | 上述伪欧式整数距离 | ATT48 |
| EUC_2D | 欧式距离四舍五入为整数 | 对应类型的 TSPLIB 实例 |
| EUCLIDEAN | 未取整的欧式距离 | 自定义连续几何练习 |

未取整欧式模式也不是旧 ATT 近似模式；旧近似还多除以 sqrt(10)。本次不把旧结果自动换算成新结果，因为末边错误和搜索轨迹都无法通过一个比例修复。

[TSPLIB FAQ](https://comopt.ifi.uni-heidelberg.de/software/TSPLIB95/tsp/TSPFAQ.html) 专门指出：遗漏距离取整可能得到看似比标准最优值更短的路线。ATT48 的标准最优值是 10628，来源是 [TSPLIB 最优值表](https://comopt.ifi.uni-heidelberg.de/software/TSPLIB95/tsp/TSP-BEST.html)。它只是正确实例的比较基准，不代表 GA 或 SA 每次都能找到这个值。

## 输入契约

- 坐标：有限、实数、非空的数值 `2×N` 矩阵，N 至少为 1。重复坐标允许。
- 距离矩阵：有限、非负、对称、方阵，且对角线为 0。
- 路线：包含每个城市恰好一次；行、列向量均可输入，输出规范为行向量。
- 溢出：即使坐标有限，过大坐标差或距离总和仍可能溢出，会明确报错。
- 本项目不接受非对称距离矩阵；不要直接拿它求解 ATSP。

48 组 ATT48 坐标直接来自原仓库，保持顺序与数值不变；加载函数不会下载数据、清理工作区或写文件。

## 自己验证

先手算三个城市的闭环，再运行 `run_tests`。四城市正方形用枚举全部排列提供一个独立的小规模最优值：边长 1 时，最优周长为 4。这种可手算的例子比“画出来看着合理”更适合作为第一道正确性检查。
