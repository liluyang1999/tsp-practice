# 做一份可以复核的实验

## 固定什么、比较什么

每次运行记录数据集、距离类型、完整参数、随机种子、目标函数评估次数和最好路线。相同种子加相同代码与运行环境可以帮助重现结果，但 GA 和 SA 使用随机数的顺序不同：相同种子不意味着相同初始解或配对随机过程。

指定 Seed 后，求解器使用 twister，并通过 [MATLAB onCleanup](https://www.mathworks.com/help/matlab/ref/oncleanup.html) 在返回或异常时恢复调用者的随机状态。省略 Seed 则使用并推进现有随机流。跨 MATLAB 版本的完全相同轨迹尚未验证；实验文件记录 version 和 computer 供追溯。

GA 的初始种群和每条被评价的子代、SA 的初始路线和每个候选邻居，都各计一次目标函数评价。run_experiments 要求两种算法恰好使用相同预算，否则报错，不输出完成结果。

**相同评估次数不等于相同计算成本**：GA 有种群选择、排序、交叉，SA 的每步操作不同。ElapsedSeconds 单独记录，包含距离矩阵构建与初始化，计时在 CSV 写出和绘图之前结束；它仍受 JIT 预热、后台进程和运行顺序影响。若研究耗时，应增加预热、交替顺序和多轮计时的专门实验。

## 输出怎么读

- runs.csv：每个算法每个种子的长度、评估数、相对标准最优值的百分比差距、耗时、完整路线。
- summary.csv：运行次数、最小值、均值、样本标准差和平均耗时。一个种子的标准差按 MATLAB std 约定为 0，不代表结果稳定。
- experiment.mat：上述表、收敛历史、参数、MATLAB 版本、机器类型、坐标与元数据。保留这个文件才能完整解释 CSV。

样本较少时，不要只凭一张收敛图宣布某算法更优。至少观察分布与失败情况，并说明参数如何选择。当前默认参数是可执行的教学起点，未经过调参或性能验证。

同一输出目录只用于一次实验。请显式提供新目录，不覆盖历史记录。代码同时检查 [mkdir 的消息 ID](https://www.mathworks.com/help/matlab/ref/mkdir.html)，因为 MATLAB 在目录已经存在时也可能返回成功状态，不能只看 status。运行失败可能留下部分输出目录；应先检查它，不能把目录存在视为完整成功，也不要自动覆盖重试。

## 待在 MATLAB 执行的测试

```matlab
addpath(fullfile(pwd, 'tests'))
run_tests
```

10 个测试组覆盖：

| 组 | 检查内容 |
| --- | --- |
| ClosingEdge | 手算 12/旧代码 13 的回归，旋转/反向不变量，单/双城市，小规模枚举最优值 |
| Distances | ATT 取整、EUC_2D、重复坐标、48 城市数据形状和已知边 |
| Validation | 非法坐标、排列、矩阵、预算、温度和 options |
| Operators | 多次交叉/变异后仍是排列，单个体选择可终止 |
| GA | 零代初始最优、准确代数、部分一代预算、长度与路线一致 |
| SA | 零外循环、准确预算、最好值单调、温度下溢、单城市 |
| Reproducibility | 同种子同结果/历史，调用者 RNG 恢复 |
| LegacyEntrypoints | 两个旧目录的包装入口、返回数据和 path 恢复 |
| ExperimentOutput | 小预算 CSV/MAT 输出、保存参数、拒绝覆盖已有目录及测试文件清理 |
| NumericClasses | 整数类参数与 double 的结果/预算/降温一致，拒绝超精确范围的 uint64 和非向量长度 |

这些是准备好的验收门槛，**本机未执行，没有 MATLAB 测试通过声明**。已完成的是逐文件审查、独立手算反例、原坐标一致性核对、包调用指向检查和旧文件保留核对；Python 辅助核对不执行 MATLAB 求解器。

## 后续机器上的验收顺序

1. 在已有 MATLAB 环境运行 checkcode 检查新增/修改的 .m 文件，处理实际诊断。
2. 运行 run_tests，记录 MATLAB 版本、输出和失败信息。
3. 运行 `run_demo(42,false)` 两次，核对 Route、Length、Info 可重现。
4. 运行 `run_demo(42,true)`，检查闭环图、坐标比例、图例与评估次数横轴。
5. 用新目录运行少量种子实验，再重跑到另一个新目录，核对除计时外的数值一致。
6. 确认每条保存路线都是 1:48 的排列，按 ATT 规则重算其长度，再扩大预算。
